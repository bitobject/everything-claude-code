# Next.js patterns (web/)

**This skill holds our decisions only.** For how a Next.js API works, read the docs that ship with the
installed version: `web/node_modules/next/dist/docs/` (`01-app/03-api-reference`, `01-app/02-guides`). `web/AGENTS.md`
(written by create-next-app and kept current by `next dev`) points agents there; `web/CLAUDE.md` imports it with
`@AGENTS.md` (template: `../../examples/web-CLAUDE.md`, relative to this skill's directory). Below, `docs/` means
`node_modules/next/dist/docs/01-app/`.

Versions: `STACK.md`. Lint config, TypeScript and React style: `coding-standards`. SEO: `seo`. Tests: `tdd-workflow`.
The files shown below (in full, or as marked excerpts) were compiled, linted (`strictTypeChecked`, boundaries,
jsx-a11y), tested and built with the pinned versions on 2026-11-13.

## Ground rules

- **Go owns the business.** Next.js renders pages and calls the Go API: no business rules, no PostgreSQL, no ORM in
  `web/`. If a page needs data the API does not return, change `api/openapi.yaml` first.
- **Contract first.** `src/lib/api/schema.ts` is generated by openapi-typescript and never edited. Types that mirror
  API payloads by hand are a bug; alias `components['schemas']['X']`.
- **Indexable pages are Server Components with complete HTML on the first response.** Client-only rendering is
  acceptable only in the cabinets.

ESLint enforces it (config in `coding-standards`): `app → features → components/lib`; a feature never imports
another feature (compose them in `app/`); `lib/api/server.ts` is imported only by `features/*/data.ts` and
`actions.ts`; `process.env` is read only in `lib/env.server.ts` and `lib/env.public.ts`. A boundary error is fixed by
moving code, never by widening the config.

Not used: full Feature-Sliced Design (layers and re-exports cost more than they give a small team), React taint APIs
(experimental; cabinet data goes browser → Go anyway), Storybook and a monorepo (one app, no shared packages yet).

## `next.config.ts`

```ts
import type { NextConfig } from 'next'

const nextConfig: NextConfig = {
  cacheComponents: true,
  partialPrefetching: true, // set explicitly; unset logs a warning
  typedRoutes: true, // <Link href> and router.push are checked against the routes
  images: { remotePatterns: [new URL('https://media.example.ru/**')] },
  // The reverse proxy forwards /api/* to Go before Next sees it; without one (dev, e2e) this rewrite does.
  // Evaluated at build: API_INTERNAL_URL must be set for `next build`.
  rewrites: () =>
    Promise.resolve([{ source: '/api/:path*', destination: `${process.env.API_INTERNAL_URL ?? ''}/:path*` }]),
}

export default nextConfig
```

- With `cacheComponents`, the segment configs `dynamic`, `dynamicParams`, `revalidate`, `fetchCache` and
  `unstable_cache` are gone; use `'use cache'`.
- `typedRoutes`: literal hrefs are checked; built ones are cast once, in `lib/routes.ts`
  (`` `/${city}/${topic}` as Route ``). Never cast hrefs elsewhere.
- **Reverse proxy and Server Actions.** Next rejects an action whose `Origin` host differs from `x-forwarded-host`
  (or `host`). The proxy must forward the public host; only if it cannot, list it in
  `experimental.serverActions.allowedOrigins` (still under `experimental` in 16.4).
- More than one Next instance: the same `NEXT_SERVER_ACTIONS_ENCRYPTION_KEY` everywhere, a `deploymentId` per
  release, and a shared `cacheHandlers` implementing `refreshTags` (`docs/02-guides/self-hosting.md`).

```ts
// src/lib/api/server.ts
import 'server-only'
import createClient, { type Client, type Middleware } from 'openapi-fetch'
import type { paths } from './schema'
import { serverEnv } from '@/lib/env.server'

const TIMEOUT_MS = 8_000

/** Every call to Go gets a deadline and a request id (the proxy's one when the caller forwards it). */
const resilience: Middleware = {
  onRequest({ request }) {
    const headers = new Headers(request.headers)
    if (!headers.has('x-request-id')) headers.set('x-request-id', crypto.randomUUID())
    return new Request(request, { headers, signal: AbortSignal.any([request.signal, AbortSignal.timeout(TIMEOUT_MS)]) })
  },
}

/** A client whose every call carries `headers` (from requestHeaders()/sessionHeaders()); one per request.
 * Captures `fetch` at creation, after instrumentation.ts patched it, so calls carry the active span's traceparent. */
export function apiFor(headers: Record<string, string | undefined>): Client<paths> {
  const client = createClient<paths>({ baseUrl: serverEnv().API_INTERNAL_URL, headers })
  client.use(resilience)
  return client
}

/** For public, cached reads: no request data. */
export const api = apiFor({})
```

```ts
// src/lib/api/forwarded.ts
import 'server-only'
import { headers } from 'next/headers'
import { pickCookie, SESSION_COOKIE } from './cookie'

type Forwarded = Record<string, string | undefined> // undefined values are not sent

/**
 * The proxy's request id and client IP for this request; Go logs and rate-limits with them. `traceparent` is not
 * forwarded by hand: instrumentation.ts propagates the active span's context on every fetch to Go.
 */
export async function requestHeaders(): Promise<Forwarded> {
  const incoming = await headers()
  return {
    'x-request-id': incoming.get('x-request-id') ?? undefined,
    'x-forwarded-for': incoming.get('x-forwarded-for') ?? undefined,
  }
}

/** requestHeaders() plus the session cookie verbatim: Go authorizes, Next only forwards. */
export async function sessionHeaders(): Promise<Forwarded> {
  const incoming = await headers()
  return { ...(await requestHeaders()), cookie: pickCookie(incoming.get('cookie'), SESSION_COOKIE) }
}
```

```ts
// src/lib/api/cookie.ts — pure, no Next imports, so Vitest and proxy.ts can use it
export const SESSION_COOKIE = '__Host-session' // HttpOnly, Secure, SameSite=Lax; set by Go

/**
 * One cookie exactly as the browser sent it ("name=value"), or undefined.
 * Not cookies().get()/toString(): Next decodes values, drops undecodable ones and re-encodes with
 * encodeURIComponent, and Go compares cookie values byte for byte.
 */
export function pickCookie(rawCookieHeader: string | null, name: string): string | undefined {
  return rawCookieHeader?.split(/;\s*/).find((pair) => pair.startsWith(`${name}=`))
}
```

- Public, cached reads use `api`. Request-time reads use `apiFor(await sessionHeaders())` (the cabinets' prefetch);
  Server Actions get the same headers from the action client's context (`apiFor(ctx.forwarded)`). Never
  `(await cookies()).toString()`: a token with `+ / =` reaches Go re-encoded and is rejected. Never read `headers()`
  inside `'use cache'`.
- `traceparent` is not forwarded by hand: `instrumentation.ts` (below) injects the active span's context into every
  fetch to Go, continuing the proxy's trace when it sent one.
- Write paths exactly as in the contract (`'/v1/leads/{leadId}'`); openapi-fetch infers every type from the literal.

### Errors from Go (RFC 9457)

A non-2xx body is a problem document `{ type, title, status, code, detail?, requestId?, errors? }` only when Go
wrote it; a proxy's 502 page is not, and openapi-fetch still types `error` as the contract's `Problem`. Read it
through one pure module, `src/lib/api/problem.ts`:

- `asProblem(body: unknown): Problem | undefined`: checks `type`, `title`, `status`, `code`; drops malformed `errors`.
- `fieldErrorCodes(problem, ['phone'])`: field errors by JSON Pointer (`"#/phone"` → `phone`), for 400 `request.invalid`.
- `retryAfterSeconds(response)`: the `Retry-After` of 429 and 503.

Branch on `code` (the operation's `x-problem-codes` lists them; treat an unknown code like its status), never on
`title` or `detail`; map codes to Russian copy in the feature. 5xx, timeouts and non-problem bodies are retryable.
Unexpected failures in reads throw `ApiError` (`lib/api/errors.ts`) to `error.tsx`.

### Cached data functions (public pages)

```ts
// src/features/landing/data.ts
import 'server-only'
import { cacheLife, cacheTag } from 'next/cache'
import { api } from '@/lib/api/server'
import type { components } from '@/lib/api/schema'
import { ApiError } from '@/lib/api/errors'
import { landingCache } from './cache'

export type Landing = components['schemas']['Landing']

export async function getLanding(city: string, topic: string): Promise<Landing | null> {
  'use cache'
  cacheLife('days') // safety net; freshness comes from tags
  cacheTag(landingCache.all, landingCache.city(city), landingCache.page(city, topic))

  const { data, error, response } = await api.GET('/v1/landings/{city}/{topic}', {
    params: { path: { city, topic } },
  })
  if (response.status === 404) return null
  if (error !== undefined) throw new ApiError(response.status, error)
  return data
}

export async function listTopLandingParams(): Promise<{ city: string; topic: string }[]> {
  'use cache'
  cacheLife('days')
  cacheTag(landingCache.all)
  const { data, error, response } = await api.GET('/v1/seo/landing-params')
  if (error !== undefined) throw new ApiError(response.status, error)
  return data
}
```

```ts
// src/features/landing/cache.ts — the feature's cache contract; Go's revalidate webhook sends the same strings
export const landingCache = {
  all: 'landings',
  city: (city: string) => `city:${city}`,
  page: (city: string, topic: string) => `landing:${city}:${topic}`,
}
```

- Return `data`, never the openapi-fetch result (`response` cannot be serialized into the cache).
- Arguments and closed-over variables form the cache key; keep them primitive.

## Cache Components (our rules)

API detail: `docs/03-api-reference/01-directives/use-cache.md`, `04-functions/cacheLife.md`, `cacheTag.md`.

- Pair every `'use cache'` with `cacheLife`; public content uses `'days'` or `'max'` plus tags. Never a profile
  that expires in under 5 minutes on an SEO route (it becomes a dynamic hole).
- Tags come from the feature's `cache.ts`: `<entity>` for lists, `<entity>:<id>` for items.
- No `new Date()`, `Date.now()`, `Math.random()` in prerendered code; timestamps come from the API.

| Where | Call | Effect |
|---|---|---|
| Server Action after the user's own write | `updateTag(tag)` | next read waits for fresh data |
| Webhook from Go | `revalidateTag(tag, 'max')` | stale-while-revalidate |
| Webhook, content removed | `revalidateTag(tag, { expire: 0 })` | next request blocks on fresh data |

Data changes start in Go, so Go calls this webhook after committing (block `/internal/` at the reverse proxy):

```ts
// src/app/internal/revalidate/route.ts
import { timingSafeEqual } from 'node:crypto'
import { revalidateTag } from 'next/cache'
import * as z from 'zod'
import { serverEnv } from '@/lib/env.server'

const Body = z.object({
  tags: z.array(z.string().min(1).max(256)).min(1).max(128),
  expireNow: z.boolean().default(false),
})

export async function POST(request: Request): Promise<Response> {
  const expected = Buffer.from(`Bearer ${serverEnv().REVALIDATE_SECRET}`)
  const actual = Buffer.from(request.headers.get('authorization') ?? '')
  if (actual.length !== expected.length || !timingSafeEqual(actual, expected)) {
    return new Response(null, { status: 401 })
  }
  const parsed = Body.safeParse(await request.json().catch(() => null))
  if (!parsed.success) return Response.json(z.flattenError(parsed.error), { status: 400 })

  for (const tag of parsed.data.tags) {
    revalidateTag(tag, parsed.data.expireNow ? { expire: 0 } : 'max')
  }
  return new Response(null, { status: 204 })
}
```

## SEO routes: generateStaticParams + ensureStatic

```tsx
// src/app/(public)/[city]/[topic]/page.tsx
import type { Metadata } from 'next'
import { notFound } from 'next/navigation'
import { getLanding, listTopLandingParams } from '@/features/landing/data'
import { LandingView } from '@/features/landing/components/landing-view'
import { LeadForm } from '@/features/leads/components/lead-form'
import { LeadFormBoundary } from '@/features/leads/components/lead-form-boundary'
import { landingPath } from '@/lib/routes'

// The complete route must be static; unlisted params wait for the full page instead of a fallback.
export const ensureStatic = 'navigation'

export async function generateStaticParams(): Promise<{ city: string; topic: string }[]> {
  return listTopLandingParams() // ≥ 1 item; others render on first visit
}

export async function generateMetadata({ params }: PageProps<'/[city]/[topic]'>): Promise<Metadata> {
  const { city, topic } = await params
  const landing = await getLanding(city, topic)
  if (!landing) notFound()
  return {
    title: landing.title,
    description: landing.description,
    alternates: { canonical: landingPath(city, topic) },
    robots: landing.indexable ? undefined : { index: false, follow: true },
  }
}

// No <Suspense> around the main content: crawlers get a request-time render, and content under a boundary
// arrives there as a fallback plus a hidden streamed segment. The page awaits its cached data instead.
export default async function LandingPage({ params }: PageProps<'/[city]/[topic]'>) {
  const { city, topic } = await params
  const landing = await getLanding(city, topic)
  if (!landing) notFound() // before anything streams: a real 404
  return (
    <main>
      <LandingView landing={landing} />
      <LeadFormBoundary>
        <LeadForm city={city} topic={topic} />
      </LeadFormBoundary>
    </main>
  )
}
```

- **No `<Suspense>` around the main content of an indexable page** (H1, text, breadcrumbs, JSON-LD, the lead form):
  the page awaits its cached data. Next renders crawlers on HTML-limited lists (YandexBot) at request time, and there
  a boundary sends its fallback first and the content later in a hidden streamed segment
  (`<div hidden id="S:…">`); verified with the YandexBot user agent. Suspense only around secondary parts (a
  client-only widget), if at all, and never `loading.tsx` above SEO content.
- `ensureStatic = 'navigation'` (16.4) is what guarantees complete HTML, also for params not prerendered at build:
  the request waits for the static result. It works with Cache Components alone; `partialPrefetching` only changes
  link prefetching. It fails `next dev`/`next build` when the route, its layouts or `generateMetadata` read
  `cookies()`, `headers()`, `searchParams`, `connection()` or uncached data (`docs/03-api-reference/03-file-conventions/02-route-segment-config/ensureStatic.md`).
- `generateStaticParams` returns at least one complete set (the build fails otherwise).
- Every data call must also work at request time: a page that works only from the build prerender returns 500 to
  YandexBot.
- `next build` calls the Go API, and prerendered HTML embeds `SITE_URL`: build once per environment.
- Indexable pagination uses path segments, not `?page=2`.
- **Unknown slugs cost a render and a Go call** (the request waits for the static result): `proxy.ts` answers
  malformed ones with 404 and redirects case duplicates (below). If the city and topic lists are known at build,
  check membership there too, from a JSON file the build writes; never fetch in proxy.
- The page loads and `LandingView` only renders props, so the view is unit-testable; e2e checks the server HTML
  under the YandexBot and Googlebot user agents (`e2e-runner`).

## The cabinets (browser → Go API)

Clients, lawyers and staff each have a personal cabinet: `/account/*`, `/cabinet/*`, `/admin/*`, under one
`(private)` route group. Their content is per user and rendered at request time (nothing personal is cached or
prerendered), every page is `noindex`, and no analytics runs there. `proxy.ts` sends a request without the session
cookie to `/login?next=…`; Go authorizes every call by role, so a lawyer's cookie on `/admin` gets Go's 403/404,
not data.

**Login is Go's.** Methods: email with a one-time code or link (no passwords), Yandex ID, VK ID, a phone code; Go
merges accounts with the same verified email. The login screens call Go through the same-origin `/api`, so Go's
`Set-Cookie: __Host-session` reaches the browser directly; OAuth redirects and email links point to Go's endpoints
under `/api`, never to a Next page, so their tokens never pass through Next (or its logs and spans). Sessions: idle
7 days, absolute 30 days (Go). After login the user lands in their role's cabinet; `?next=` is followed only when it
is a path inside that cabinet (an absolute URL or another cabinet goes to the role's home).

The browser calls Go same-origin under `/api` (the reverse proxy strips the prefix), so the HttpOnly cookie works
without CORS and Go's `http.CrossOriginProtection` sees the origin.

```tsx
// src/app/(private)/providers.tsx
'use client'
import type { ReactNode } from 'react'
import { QueryCache, QueryClient, QueryClientProvider } from '@tanstack/react-query'
import { asProblem } from '@/lib/api/problem'
import { loginPath } from '@/lib/routes'

// openapi-react-query throws the error body: a Problem from Go, or anything a proxy returned.
const isRetryable = (error: unknown): boolean => {
  const problem = asProblem(error)
  return problem === undefined || problem.status >= 500
}

function makeQueryClient(): QueryClient {
  return new QueryClient({
    defaultOptions: { queries: { staleTime: 30_000, retry: (count, error) => count < 2 && isRetryable(error) } },
    queryCache: new QueryCache({
      onError: (error) => {
        // One place for an expired session.
        if (asProblem(error)?.status === 401) window.location.assign(loginPath(window.location.pathname))
      },
    }),
  })
}

let browserClient: QueryClient | undefined
function getQueryClient(): QueryClient {
  if (typeof window === 'undefined') return makeQueryClient() // isolate server renders
  browserClient ??= makeQueryClient()
  return browserClient
}

export function Providers({ children }: { children: ReactNode }) {
  return <QueryClientProvider client={getQueryClient()}>{children}</QueryClientProvider>
}
```

### Server prefetch + HydrationBoundary

The first screen comes with its data: the page starts the query on the server with a server client (internal URL,
session cookie) and hands the pending query to the browser, which reads the same key. openapi-react-query keys are
`[method, path, init]` without the base URL or client headers, so both sides share them; that is also why the cookie
goes into the client (`apiFor`), never into `init`. Recipe: `docs/02-guides/client-side-data-fetching/tanstack-query.md`.

```ts
// src/features/leads/cache.ts — query keys of the feature (cabinet data is per user: TanStack only, no cache tags)
export const leadsCache = {
  leadInit: (leadId: string) => ({ params: { path: { leadId } } }),
  lead: (leadId: string) => ['get', '/v1/leads/{leadId}', leadsCache.leadInit(leadId)] as const,
}
```

```ts
// src/features/leads/data.ts
import 'server-only'
import { noop, type QueryClient } from '@tanstack/react-query'
import createQueryClient from 'openapi-react-query'
import { sessionHeaders } from '@/lib/api/forwarded'
import { apiFor } from '@/lib/api/server'
import { leadsCache } from './cache'

/** Starts the cabinet's lead query on the server without awaiting it; the browser reads the same key. */
export async function prefetchLead(queryClient: QueryClient, leadId: string): Promise<void> {
  const $server = createQueryClient(apiFor(await sessionHeaders())) // the session cookie, verbatim
  // query() replaces the deprecated prefetchQuery() (TanStack 5.107); a failure stays in the cache, the browser shows it.
  void queryClient.query($server.queryOptions('get', '/v1/leads/{leadId}', leadsCache.leadInit(leadId))).catch(noop)
}
```

```tsx
// src/app/(private)/cabinet/leads/[leadId]/page.tsx

      })}
    >
      <LeadCard leadId={leadId} />
    </HydrationBoundary>
  )
}
```

### Which mutation path

- **Public forms (lead forms): Server Actions**, progressively enhanced; they work without JavaScript.
- **Cabinet interactions: `$api.useMutation`** with invalidation of the keys from the feature's `cache.ts` (plus
  `router.refresh()` when the screen also has server-rendered parts). Server Actions run one at a time per client,
  which suits a form, not a list of quick actions.

## Server Actions and forms: the lead form

Server Actions are public POST endpoints. Every action is built with **next-safe-action** from one module:
`actionClient` for public forms, `sessionActionClient` in the cabinets. Both validate the input with a zod schema,
forward the request headers Go needs, never send an exception's text to the browser, and let Go decide.

```ts
// src/lib/api/action-client.ts
import 'server-only'
import { createSafeActionClient } from 'next-safe-action'
import { requestHeaders, sessionHeaders } from './forwarded'

/** Server Actions of public forms: the context carries the proxy's client IP and request id for Go. */
export const actionClient = createSafeActionClient({
  // Never send an exception's text to the browser; the log line has the error name and the request id has the rest.
  handleServerError: (error) => {
    console.error('Server Action failed', error.name)
    return 'Не удалось выполнить действие. Попробуйте ещё раз.'
  },
}).use(async ({ next }) => next({ ctx: { forwarded: await requestHeaders() } }))

/** Server Actions in the cabinets: also the session cookie, verbatim. Go authorizes every call. */
export const sessionActionClient = actionClient.use(async ({ next }) =>
  next({ ctx: { forwarded: await sessionHeaders() } }),
)
```

The lead form's decisions (full verified implementation and tests: `../../examples/web-lead-form.md`, relative to
this skill's directory):

1. **A `stateAction`, passed straight to React's `useActionState`.** Its `(previous result, FormData)` signature is
   what React calls, so the form works before hydration and without JavaScript (verified by a no-JS submit).
   next-safe-action's own `useStateAction` hook dispatches through a client wrapper, which loses that: don't use it
   for public forms.
2. **React 19 resets uncontrolled fields after every action, also when it returns an error.** The schema's
   validation errors are shaped (`handleValidationErrorsShape`) to carry what the visitor typed, Go's answers come
   back as typed `data` with the same `values`, and inputs render them as `defaultValue`. One pure
   `leadFormView(result)` turns the result into what the form shows.
3. **The request body is an object literal of the parsed fields**, so a field the contract lacks fails `tsc`. The
   schema normalizes the phone to the contract's `^\+7[0-9]{10}$`; a form that needs another field (a name) changes
   the contract first.
4. **`Idempotency-Key`** (a quoted Structured Field String): minted in the browser at the first submit (never during
   render: the page is prerendered, a key in the HTML would be shared by everyone), kept in a hidden input for
   retries, minted by the action when the field is empty (no JS). A 5xx, a timeout or a proxy page keeps the key; Go's
   422 `idempotency.key_reused` (the visitor edited the input after an error) is retried once with a new key.
5. **Anti-spam in the action, never sent to Go**: a honeypot field (filled → pretend success) and the fill time the
   browser measures (too fast → the generic retry message). Without JS there is no timing; the honeypot still works.
   Yandex SmartCaptcha (built with the first real form): its widget writes `smart-token` into the form, the action
   passes it to Go as the contract's `createLead` declares it, and Go verifies it. A token is single-use and valid
   5 minutes: reset the widget after an error. Without JavaScript there is no token, and Go accepts such submissions
   under stricter limits. Per-IP limits live in the reverse proxy.
6. **Deploy skew.** A page opened before a deployment posts an action ID that no longer exists ("Failed to find
   Server Action"); the action then throws on the client instead of returning a result. A `catchError` boundary
   (`unstable_isUnrecognizedActionError` from `next/navigation`) offers a reload and keeps the typed phone in
   `sessionStorage` until the form restores it.

```ts
// src/features/leads/actions.ts
'use server'
import { flattenValidationErrors } from 'next-safe-action'
import { actionClient } from '@/lib/api/action-client'
import { asProblem, retryAfterSeconds } from '@/lib/api/problem'
import { apiFor } from '@/lib/api/server'
import { idempotencyKeyOf, LeadFormInput, leadFormValues } from './schema'
import { submitLeadForm, type CreateLeadResult } from './submit'
import type { LeadFormData, LeadValidationErrors } from './form'

// A stateful action: React's useActionState calls it with (previous result, FormData), which also works
// before hydration and without JavaScript.
export const submitLead = actionClient
  .inputSchema(LeadFormInput, {
    // React resets the form after every action: send what was typed back with the errors.
    handleValidationErrorsShape: (errors, { clientInput }): Promise<LeadValidationErrors> => {
      const { fieldErrors } = flattenValidationErrors(errors)
      const phone = fieldErrors.phone?.[0]
      return Promise.resolve({
        fieldErrors: phone === undefined ? {} : { phone },
        pageOutdated: phone === undefined, // only the page's hidden city/topic failed
        values: leadFormValues(clientInput),
        idempotencyKey: idempotencyKeyOf(clientInput),
      })
    },
  })
  .stateAction<LeadFormData>(async ({ parsedInput, clientInput, ctx }) => {
    const api = apiFor(ctx.forwarded) // client IP and request id; a public form sends no cookie
    return submitLeadForm(parsedInput, leadFormValues(clientInput), {
      newIdempotencyKey: () => crypto.randomUUID(),
      send: async (body, key): Promise<CreateLeadResult> => {
        try {
          const { error, response } = await api.POST('/v1/leads', {
            params: { header: { 'Idempotency-Key': `"${key}"` } }, // a Structured Field String: quoted
            body,
          })
          if (error === undefined) return { kind: 'created' }
          return {
            kind: 'problem',
            status: response.status,
            problem: asProblem(error),
            retryAfterSeconds: retryAfterSeconds(response),
          }
        } catch (error: unknown) {
          console.error('createLead: Go API unreachable', error instanceof Error ? error.name : 'unknown')
          return { kind: 'unreachable' } // timeout or network: the retry reuses the key, so no duplicate
        }
      },
    })
  })
```

```ts
// src/features/leads/form.ts (excerpt) — type-only imports: zod and server code stay out of the browser bundle
/** The input schema's errors, shaped to carry the typed values back. */
export type LeadValidationErrors = {
  fieldErrors: LeadFieldErrors
  pageOutdated: boolean // only the page's own hidden fields failed
  values: LeadFormValues
  idempotencyKey?: string
}

/** The action's answer once the input passed the schema: Go's answer or the anti-spam verdict. */
export type LeadFormData =
  | { status: 'sent' }
  | { status: 'invalid'; values: LeadFormValues; fieldErrors: LeadFieldErrors; idempotencyKey: string }
  | { status: 'rejected'; values: LeadFormValues; code: string; retryAfterSeconds?: number; idempotencyKey: string }
  | { status: 'failed'; values: LeadFormValues; idempotencyKey?: string } // retry with the same key

export type LeadFormState = SafeActionResult<string, typeof LeadFormInput, LeadValidationErrors, LeadFormData>
```

- Annotate `handleValidationErrorsShape`'s return type (`Promise<LeadValidationErrors>`): the inferred literal type
  makes the action's result type differ from the state type and `useActionState` rejects the action.
- The input schema takes `FormData` (`z.instanceof(FormData).transform(Object.fromEntries).pipe(z.object(…))`):
  `z.object`, never `z.strictObject`, because the form also posts React's hidden `$ACTION_*` fields (they are not
  stripped).
- A `'use server'` file exports only actions. Parsing lives in `schema.ts`, the flow in `submit.ts` (no Next
  imports, tested with a fake `send`), copy and `leadFormView` in `copy.ts`.
- Cabinet actions use `sessionActionClient`; never trust a user id from the form. Most cabinet interactions are
  `useMutation` instead (below).
- After a write the user must see immediately, call `updateTag(...)` or `redirect()` to a page that reads fresh data.
- The `ym-disable-keys` class keeps the field out of Metrica's Webvisor recording (seo skill).

## `proxy.ts`

```ts
// src/proxy.ts
import { NextResponse, type NextRequest } from 'next/server'
import { SESSION_COOKIE } from '@/lib/api/cookie'
import { landingPath, loginPath } from '@/lib/routes'

// The personal cabinets: clients, lawyers, staff. Go decides who may see what; this only skips a useless render.
const CABINETS = ['/account', '/cabinet', '/admin']
const inCabinet = (path: string): boolean => CABINETS.some((c) => path === c || path.startsWith(`${c}/`))
const LANDING = /^\/([^/]+)\/([^/]+)$/
const isSlug = (s: string): boolean => /^[a-z0-9]+(?:-[a-z0-9]+)*$/.test(s)

export function proxy(request: NextRequest) {
  const { pathname } = request.nextUrl
  if (inCabinet(pathname)) {
    // Optimistic check only: Go authorizes every call.
    if (!request.cookies.has(SESSION_COOKIE)) return NextResponse.redirect(new URL(loginPath(pathname), request.url))
    return NextResponse.next()
  }

  // /[city]/[topic] has ensureStatic: every unlisted slug costs a blocking render and a Go call. Stop junk here.
  const [, city = '', topic = ''] = LANDING.exec(pathname) ?? []
  if (isSlug(city) && isSlug(topic)) return NextResponse.next()
  if (isSlug(city.toLowerCase()) && isSlug(topic.toLowerCase())) {
    return NextResponse.redirect(new URL(landingPath(city.toLowerCase(), topic.toLowerCase()), request.url), 308)
  }
  return new NextResponse(null, { status: 404 })
}

export const config = {
  // The cabinets, plus two-segment paths that can be landings. Never _next/, api/ or files.
  matcher: [
    '/account/:path*',
    '/cabinet/:path*',
    '/admin/:path*',
    '/((?!_next/|api/|internal/|account/|cabinet/|admin/|login/)[^/.]+)/([^/.]+)',
  ],
}
```

- Redirects, cookie-presence checks and cheap URL checks only; no fetches, no `'use cache'`. Always Node.js.
- Always set a `matcher`, and unit-test it (`unstable_doesMiddlewareMatch` from `next/experimental/testing/server`):
  a two-segment matcher also matches `/_next/image`. A Server Action is a POST to its page and can slip past a
  matcher: proxy is never the auth boundary.

## OpenTelemetry

```ts
// src/instrumentation.ts
import type { ReadableSpan, SpanProcessor } from '@opentelemetry/sdk-trace-base'
import { registerOTel } from '@vercel/otel'
import { serverEnv } from '@/lib/env.server'

/** Query strings can carry tokens or click ids: export URLs without them (span names are route templates). */
const stripQueryStrings: SpanProcessor = {
  onStart: () => undefined,
  onEnd: (span: ReadableSpan) => {
    for (const key of ['http.target', 'http.url', 'url.full', 'url.query']) {
      const value = span.attributes[key]
      if (typeof value === 'string' && value.includes('?')) span.attributes[key] = value.slice(0, value.indexOf('?'))
    }
  },
  forceFlush: () => Promise.resolve(),
  shutdown: () => Promise.resolve(),
}

// Next's spans (request, render) and the fetch calls to Go, exported over OTLP as the standard
// OTEL_EXPORTER_OTLP_* variables configure it; without them nothing is exported.
export function register() {
  registerOTel({
    serviceName: 'web',
    spanProcessors: [stripQueryStrings, 'auto'], // before the exporter's processor
    instrumentationConfig: {
      // The active span's traceparent goes to the Go API only, never to third parties (images, analytics).
      fetch: { propagateContextUrls: [serverEnv().API_INTERNAL_URL] },
    },
  })
}
```

- `@vercel/otel` is what the bundled docs recommend (`docs/02-guides/open-telemetry.md`); their manual `NodeSDK`
  setup is equivalent but imports `@opentelemetry/sdk-trace-node`, which OpenTelemetry JS 3.0 deprecated. `@vercel/otel`
  2.x needs the OpenTelemetry 2.x packages (`@opentelemetry/api` below 1.10): pin that line (`STACK.md` §4).
- Export is configured only by the standard variables: `OTEL_EXPORTER_OTLP_ENDPOINT` (or `…_TRACES_ENDPOINT`),
  `OTEL_EXPORTER_OTLP_PROTOCOL` (`http/protobuf` by default, `http/json`), `OTEL_EXPORTER_OTLP_HEADERS`.
- `propagateContextUrls` is required: by default `@vercel/otel` propagates context only to Vercel deployment URLs.
  The server client captures `fetch` after `register()` ran, so its calls to Go carry the active span's
  `traceparent` (verified: Go's parent span is the render's `fetch` span, inside the proxy's trace when the proxy
  sent one).
- No personal data in spans: Next names spans by route template (`GET /cabinet/leads/[leadId]`,
  `render route (app) …`), the processor above drops query strings, and URLs never carry personal data (contract
  rule; login tokens go to Go under `/api`). Custom spans get ids, never input values.

## Special files, environment, images

- `error.tsx` (`'use client'`, props `{ error: unknown; retry }`), `global-error.tsx` (own `<html lang="ru">`),
  `not-found.tsx` (404 only before streaming starts), `loading.tsx` (cabinets only, never above SEO content),
  `catchError` from `next/error` for component-level boundaries: `docs/03-api-reference/03-file-conventions/`.
- Configuration is read once, in `src/lib/env.server.ts` (`import 'server-only'`, zod: `API_INTERNAL_URL`,
  `SITE_URL`, `SITE_INDEXABLE`, `REVALIDATE_SECRET`) and `src/lib/env.public.ts` (`NEXT_PUBLIC_*`, referenced
  literally because they are inlined at build). Lint rejects `process.env` anywhere else. `.env*` files live in `web/`.
- `next/image` for content images with `width`/`height` (or `fill` + `sizes`). **The single LCP image gets
  `loading="eager"` and `fetchPriority="high"`**: `fetchPriority` alone still renders `loading="lazy"`, and
  `priority` is deprecated. `preload` instead only when the image must be discovered from `<head>`, and never
  together with `loading` or `fetchPriority`. Everything below the fold stays lazy.
- Fonts via `next/font` with the `cyrillic` subset (generators add only `latin`), exposed to Tailwind through a CSS
  variable. Design tokens live in `globals.css` under `@theme`.
- SEO pages ship near-zero JS: check with `pnpm next analyze --output`; third-party scripts through `next/script`.

## Anti-patterns

| Don't | Do |
|---|---|
| `middleware.ts` / `export function middleware` | `src/proxy.ts` / `export function proxy` |
| `(await cookies()).toString()` forwarded to Go | `apiFor(await sessionHeaders())`: the raw cookie |
| `<Suspense>` around the main content of an SEO page | await the cached data in the page |
| a bare `'use server'` function | `actionClient`/`sessionActionClient` with an input schema |
| `useStateAction` or a client wrapper around a public form's action | the `stateAction` straight into `useActionState` |
| forwarding the incoming `traceparent` by hand | `instrumentation.ts` propagates the active span |
| a form whose error state has no `values` | return `values`, render them as `defaultValue` |
| `body: parsed.data`, fields the contract lacks | an object literal of the parsed fields |
| a key, `Date.now()` or `Math.random()` rendered into prerendered HTML | mint in the browser after hydration |
| `fetchPriority="high"` alone on the LCP image | `loading="eager"` + `fetchPriority="high"` |
| `void queryClient.prefetchQuery(...)` (deprecated in TanStack 5.107) | `void queryClient.query(...).catch(noop)` |
| `cookies()`/`headers()` inside `'use cache'` | read outside, pass a primitive argument |
| `revalidateTag('x')` | `revalidateTag('x', 'max')`, or `updateTag('x')` in a Server Action |
| `generateStaticParams` returning `[]` | at least one param |
| one feature importing another | compose both in `app/` |
| editing `lib/api/schema.ts`, hand-written DTOs | change `api/openapi.yaml`, run `make generate` |
| `next lint` | `pnpm lint` (`eslint .`) |
